# Efficient Agent Trajectory Annotation with onPanda
**Access the agent environment dynamically and label multi-turn SFT and preference data with tool calls online**

Existing annotation tools support assigning attributes or adding textual feedback to completed agent trajectories. Editing those trajectories to construct SFT data presents two further challenges:

1. Agent trajectories alternate between tool calls and environment feedback. After a tool call is changed, the original continuation is often no longer valid: the corrected call must be executed, and generation must continue from the new feedback.
2. Model outputs have become more complex: alongside `content`, they can include lengthy `reasoning` and structured `tool_calls`. Annotators need to understand and edit reasoning and tool arguments, and sometimes account for environment state. Manual rewriting is costly, and building the annotation interface is also more difficult.

[onPanda](https://on-panda.github.io/research/) is an open-source LLM alignment data annotation tool that supports agent trajectories. Its core idea is to correct the generation process. onPanda connects to existing agent environments and lets annotators efficiently edit `reasoning`, `content`, and `tool_calls` in model responses. This enables interactive trajectory annotation in real environments, producing SFT and preference data with high on-policy fidelity.

### Annotation interface and interaction

While reading the model output, annotators locate the first inappropriate token and either select a replacement from the candidates or type the correction directly. onPanda then truncates the content after that position and lets the model continue from the corrected prefix.

### Connect your own agent tools and environment

Annotating agent trajectories in onPanda relies on real environment feedback. There are two ways to connect the target environment:

1. onPanda supports MCP natively, so tools exposed through MCP can be connected directly to the annotation workflow.
2. For an existing agent harness, [harness_to_mcp](https://github.com/on-panda/harness_to_mcp) exposes its tools and environment through MCP for use in onPanda's interactive annotation workflow.
    - harness_to_mcp already supports Claude Code, Codex, and OpenCode. For other harnesses, a coding agent can use the existing adapters as references to implement the integration.

In addition to an environment connection, token-level correction requires an API that supports continuation from an assistant prefix; candidate selection requires `top_logprobs`. See [API compatibility](API_compatibility.md).

### Benefits of token-level correction

onPanda's token-level correction workflow offers several benefits:

- Faster annotation: candidate selection and local edits guide the model's continuation, reducing manual rewriting.
- SFT and preference data from the same workflow: accepted responses and branches before and after correction are preserved, allowing preference pairs to be constructed under the same context.
- Token-level supervision: correction positions and replacement content provide precise supervision with naturally paired positive and negative tokens. Task-specific step boundaries can also be used to construct process reward data for PRM training.
- High on-policy fidelity: most tokens are generated by the rollout model used during annotation, with human intervention limited to local corrections.
- Lower annotator workload: the paper's user study found lower overall workload scores for onPanda than for preference annotation and manual post-editing.
- Support for custom turn-level attribute annotation.

Annotation results are saved as `.panda.json` files. The companion [Python library](https://github.com/on-panda/on-panda-python) exports SFT, preference, and token-level correction data. See our paper, [onPanda: Efficient Annotation of On-Policy Alignment Data for LLMs and Agents via Token-Level Correction](https://arxiv.org/abs/2609.24983), for experiments and further discussion.

### Start your own agent annotation project

onPanda has been used internally at StepFun to produce hundreds of thousands of alignment data samples across image, audio, and agent trajectory tasks. Its component-based design allows core components to be imported and reused in existing annotation platforms. See the [onPanda integration examples](https://github.com/on-panda/on-panda/tree/main/apps/integration-example).
